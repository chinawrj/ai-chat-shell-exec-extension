# AI Chat Shell Exec v0.11.7

This release makes failed local Skill installation immediately diagnosable without exposing installer output to the AI chat page, and replaces the old absolute installer timeout with a true output-idle deadline.

It also restores reliable Draw.io replacement rendering on Chrome 151 by keeping the transparent sandbox staging frame inside the viewport, where Chromium continues its asynchronous SVG layout and failure timers.

## Local failure results

- A nonzero installer exit, signal termination, or output-idle timeout leaves the Skill uninstalled and keeps its row retryable.
- The shell server returns a bounded stdout/stderr tail only for those execution failures. The extension background sanitizes ANSI, control, and bidirectional formatting characters, retains the detail in one-use memory, and removes raw output before replying to the chat content script.
- The initiating tab opens a separate `chrome-extension://` result window showing the Skill, exit code or signal, duration, stderr, and optional stdout. Details never enter the chat page DOM, composer, AI messages, pending delivery queue, command ledgers, logs, install-state JSON, or persistent/session storage.
- The result window renders all installer text through `textContent`, warns that output may contain sensitive data, supports a user-initiated copy, and consumes its short-lived token exactly once.

## 600-second output-idle semantics

- Skill installers no longer have a fixed total runtime limit. The server terminates the installer process group only after 600 consecutive seconds without stdout or stderr.
- Either stream resets the shared idle clock, including after the bounded diagnostic capture is already full. Captured diagnostics retain the tail where failure messages normally appear.
- Success now strictly requires explicit exit code 0 with no signal and no idle timeout. Null/unknown exit codes and signal termination can no longer become installed receipts.
- Main-shell exit and idle kill both have bounded stdio-drain/process-group settlement. A descendant that inherits the output pipes cannot permanently block the serialized installation queue.
- Browser-side Skill install WebSockets have no absolute watchdog and use the existing 20-second Chrome MV3 heartbeat, so a valid long installer is not reported as a transport failure after roughly 130 seconds.
- Skill protocol 4 rejects mixed old/new extension-server pairs whose installer timeout and diagnostic semantics are incompatible.

## Regression coverage

- Focused server tests cover stdout/stderr activity, capture-saturated idle resets, real idle termination, bounded output tails, signal and unknown-exit failures, and descendants holding inherited pipes.
- Background/content/result-page tests cover heartbeat/watchdog policy, token ownership and one-use consumption, output sanitization, plain-text rendering, trusted-click flow, Retry state, and the absence of raw output from the chat content script and extension storage.
- The real unpacked-Chrome Skills E2E executes an installer that emits stdout/stderr and exits 23, verifies the extension-owned failure window and Retry state, proves the Skill remains uninstalled, and confirms the composer and submitted AI-message count do not change.
- The Draw.io-only Chrome 151 E2E replaces a current preview through the transparent staging frame and verifies valid, malformed, and renderer-failure outcomes remain latest-only.
