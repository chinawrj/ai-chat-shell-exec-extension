# AI Chat Shell Exec v0.11.6

This release fixes two intermittent browser-side failures without changing shell execution or the pinned v0.8.6/v0.8.9 send actuator.

## Draw.io renderer recovery

- The parent no longer applies one combined 7-second budget to viewer cold startup, rendering, and result delivery.
- Viewer startup and render acceptance now have separate visible-page-time checks; background-tab time does not consume either budget.
- A lost ready message is recovered by the iframe load event. If the first iframe does not accept the render request in time, one fresh local iframe retry absorbs the transient failure.
- The final attempt is not destroyed by another parent render deadline. After the packaged synchronous renderer returns, the isolated viewer detects an existing SVG immediately, observes asynchronous SVG insertion, and applies its own 15-second visible-time output check.
- Channel, iframe source, artifact id, and generation checks continue to reject stale or mismatched completions.
- Selecting an already-rendered or cached invalid/failed artifact is still a latest-only decision: it cancels any different staging renderer before restoring the selected local outcome.
- Final validation/render failures still clear the old preview and send one bounded error report; successful previews remain local and silent.

## Skill protocol and composer recovery

- A host syntax highlighter may render a canonical field such as `catalog-version:2` as `catalog-version:\n2` in `innerText`. The extension now falls back to the same code node's canonical `textContent` only when the two representations differ by line breaks alone and the complete Skill envelope passes strict validation.
- Truly malformed naked numeric lines, hidden extra content, duplicate/unknown fields, and mismatched identities still fail before background/server work.
- A stale remembered tool/sidebar input can no longer block a restored strong chat composer. An explicit **Bind input** selection remains authoritative.
- Pending Skill protocol replies retain catalog version, memory entry, challenge, and reason across persistence, and a fresh forced synchronization removes only obsolete never-written Skill sync deliveries.
- That Force Sync removal intent is durable across an immediate refresh/crash; recovery drops a marked stale queued entry but preserves an entry whose phase already advanced to inserted.

## Regression coverage

- Deterministic behavior tests cover hidden-page pause/resume, cancellation, first-attempt retry/final-attempt waiting, message phase transitions, stale source/channel/artifact rejection, synchronous/asynchronous/missing SVG outcomes, and observer/timer/listener cleanup.
- Skill DOM tests cover a valid split catalog version, a real naked numeric line, hidden extra content, one background ACK, and zero background work for rejection.
- Real unpacked-Chromium tests cover repeated Draw.io success/failure/recovery, A→B→A and cached-invalid staging supersession, plus a focused weak input while the real composer is absent after a malformed Skill response is queued; composer recovery writes and submits exactly once.
