# AI Chat Shell Exec v0.11.14

This release makes the configured execution environment file available to controlled Skill loading as well as shell commands and trusted Skill lifecycle scripts.

## Skill load environment expansion

- Every valid variable declared in `AI_CHAT_SHELL_ENV_FILE` is eligible for `$NAME` or `${NAME}` expansion during an exact-id/SHA Skill load; its name does not need to be repeated in `AI_HELPER_SKILL_ENV_ALLOWLIST`.
- The file is reread before every load. Editing a value takes effect on the next request without restarting the shell server and does not change the raw Skill catalog SHA or monotonic version.
- An env-file value overrides a same-named shell-server process value. `AI_HELPER_SKILL_ENV_ALLOWLIST` remains the way to expose additional variables that exist only in the server process environment.
- Expansion remains one-pass. Claude runtime placeholders stay literal, `${CLAUDE_SKILL_DIR}` still resolves to the validated Skill directory, and server-owned Skill-root placeholders cannot be spoofed by either environment source.
- The existing safe-file, UTF-8, syntax, entry/value/total-size, and expanded-reply limits remain enforced. A malformed, missing, symlinked, unsafe, or oversized env file fails the Skill load without returning its values or filesystem path.
- Only values referenced by the installed `SKILL.md` enter the bounded load response; unreferenced env-file values are not copied into the AI message.

## First-response URL assignment

- ChatGPT may replace the provisional new-chat `/` URL with a permanent `/c/<id>` or `/uc/<id>` URL while the first helper is still reading settings, running in the backend, recovering a lost MV3 runtime channel through read-only shell/board status, or entering the persistent delivery queue. That one proven route assignment now preserves the active execution lock and exact originating helper/turn ownership.
- Runtime recovery revalidates that ownership before and after every status await, never resends the original shell/board request, and accepts the recovered result only for the retained exact turn. Force continues to use its strict original route boundary.
- Pending-result creation revalidates ownership after loading local state and again after its durable write. Invalidated continuations clean up only their own exact entry, cannot delete a newer same-call replacement, and cannot overwrite a newer helper's active panel state. Force backend and validation results remain bound to their original route through this persistence window.
- Restored ordinary queued, inserted, or submitted-unconfirmed output has no volatile DOM proof and is never migrated to a new route, including an apparent provisional-to-permanent assignment. Live pending output still follows the one proven handoff through its exact candidate/turn guard. Already-submitted entries may cross only to finish the server presentation receipt, without composer writes, sends, or old-chat status updates.
- A retained first response receives its result exactly once: no backend replay, no second composer write, and no second submission.
- Transcript replacement, navigation from an already permanent conversation, a changed/detached helper, or a second route fails closed. Work that already started may finish locally, but its result cannot enter the unrelated chat.
- The original v0.8.6/v0.8.9 send actuator is unchanged; this fix is confined to pre-dispatch origin validation, route lifecycle handoff, durable queue staging, and delivery guards.

## Draw.io route ownership

- A Draw.io render completion and its optional error reply now retain the exact originating helper and ChatGPT turn across settings, pending-state load/persist, and composer-delivery awaits.
- The retained first response may cross one proven `/` to `/c/<id>` or `/uc/<id>` assignment and deliver one error reply. Transcript replacement, navigation from one permanent conversation to another, or a second route discards the stale completion without updating the new panel or composer.

## Validation

- Focused catalog tests cover automatic env-file eligibility, same-name override, process-only non-allowlisted preservation, one-pass replacement, Claude/runtime placeholder precedence, hot rereads, unchanged catalog identity, and malformed/missing-file failures.
- Server protocol tests exercise the same behavior through the real high-level Skill request path.
- Real unpacked-Chrome E2E covers successful load delivery, live env-file updates with the same catalog SHA, and one bounded malformed-file error delivery.
- Focused route tests cover URL changes during the final settings read, an in-flight backend request, and MV3 channel-loss status recovery for shell and board, including retained, replaced-transcript, already-permanent second-route, and Force-boundary cases.
- Deferred-storage regressions cover a retained exact-turn enqueue, transcript replacement followed by a newer active helper, exact-entry cleanup, same-call replacement protection, and strict Force backend/validation persistence boundaries.
- Draw.io route regressions gate settings and local persistence, cover same-page delivery plus retained provisional-route delivery, and reject transcript replacement, permanent-to-permanent navigation, second-route, and stale render-completion side effects.
- Restored-pending regressions cover queued, inserted, and submitted-unconfirmed shell and Draw.io errors across both permanent-chat navigation and apparent provisional URL assignment, plus submitted/presented receipt-only cleanup with zero composer or panel effects.
- Four isolated real-Chrome cases reproduce the provisional-to-permanent URL change around final helper rendering, a real delayed tmux command, and an already-inserted result whose composer is replaced with the exact text; the retained transcript receives one result without replay or rewrite, while the replaced transcript receives none.

This release uses shell server protocol 12 and Skill protocol 6. Restart the foreground shell server, reload the unpacked extension, and refresh affected chat tabs after upgrading.
