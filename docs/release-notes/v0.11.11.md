# AI Chat Shell Exec v0.11.11

This release adds a controlled execution-environment file, completes the trusted local Skill lifecycle with uninstall support, and includes the latest ChatGPT DOM and restrictive-CSP Draw.io compatibility fixes.

## Guaranteed Force run recovery

Every latest detected executable or Skill helper now starts a 20-second accumulated semantic-idle clock. The clock is keyed to the page lifecycle, helper kind, and payload semantics, so repeated scans, unrelated UI activity, and equivalent DOM replacement cannot keep resetting it. Only a real helper/backend operation pauses the clock; it resumes afterward. At the deadline the compact action row exposes **Force run**.

**More → Setup & recovery** also contains a permanently discoverable **Force run** entry. It is enabled immediately when a current executable/Skill helper exists and disabled only when no eligible helper exists or a helper operation is active. The separate `Skills vN` header chip remains in place and retains its catalog/update behavior.

Both **Force run** and **Process Skill** now require a real trusted browser click. Host-page scripts and synthetic `.click()` events are rejected before any executable or local Skill operation, while real CDP/browser input is covered end to end.

## Controlled execution environment

Set `AI_CHAT_SHELL_ENV_FILE=/absolute/path/to/runtime.env` before starting the shell server. The file accepts one `NAME=VALUE` or `export NAME=VALUE` declaration per line, plus blank lines and `#` comment lines. It is parsed as bounded UTF-8 data and is never sourced or command-expanded.

The server rereads it immediately before each ai-helper shell command and each trusted Skill `install.sh` or `uninstall.sh`. Its values are not injected into board/file helpers, Skill loading, server health, logs, ledgers, protocol replies, or the server process environment. Invalid, duplicate, unsafe, symlinked, oversized, or malformed input fails before execution.

The exact environment-file content SHA is part of authoritative shell dedup identity. The same completed command and unchanged file may deduplicate; changing the file makes the same command eligible to execute again.

## Skill uninstall

An installed Skill with a safe adjacent `uninstall.sh` now exposes **Uninstall** in `View Skills`. A trusted click and native confirmation bind the exact Skill, catalog, and uninstaller SHA. The server executes a private immutable `/bin/sh` snapshot from the Skill directory through the same serialized, heartbeat-backed, 600-second output-idle lifecycle as installation.

Exit code 0 atomically clears the exact installed record before refreshing the catalog, so a successful uninstaller that changes a lifecycle file cannot produce a contradictory failure while the Skill silently disappears. Nonzero exit, signal, idle timeout, stale preflight, launch failure, or state-write failure does not proactively clear an unchanged identity. If the failed script or another writer changed `SKILL.md`/`install.sh`, fail-closed reconciliation still resets that changed identity instead of reusing its old receipt. Raw diagnostics remain in one-use extension memory and never enter the chat page or AI messages.

## Compatibility fixes included

- ChatGPT's current outermost authored-message DOM, composer actuator morph, and first new-chat route assignment are handled with exact host-scoped ownership proofs. Nested/user/sponsored/history/rewritten/expired/second-route copies remain rejected.
- Draw.io preview can use a nonce-bound sandboxed `srcdoc` renderer when a host's `frame-src` policy blocks the packaged extension iframe. XML remains outside generated HTML and travels only through the channel-bound message.

## Validation

- Dedicated environment parser, safe-file, quoting, boundary, and no-value-leak tests.
- Real tmux lifecycle checks for configured values, unchanged dedup, changed-file execution, and malformed-file pre-execution rejection.
- Real `/bin/sh` Skill install/uninstall snapshot tests plus protocol, background, trusted-click, double-click, failure-window, state, and composer-isolation regressions.
- Real unpacked-system-Chrome E2E for shell environment injection/hot reload and the complete Skill install/uninstall browser flow.
- Focused fake-clock positive/negative/boundary tests plus an isolated real-Chrome page that repeatedly replaces the detected helper DOM throughout the full 20-second idle interval, then proves Force run appears and dispatches exactly on an explicit click.
- Full repository test suite and independent positive/negative release review.

This release requires shell server protocol 12 and Skill protocol 5. Restart the foreground server, reload the unpacked extension, and refresh affected chat tabs after upgrading.
