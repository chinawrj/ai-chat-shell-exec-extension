# AI Chat Shell Exec v0.11.2

This release adds a bundled `skill-creator` for creating or updating reusable `SKILL.md` instructions in the local AI Chat Shell Exec Skills catalog.

## Configurable Skill destination

- The bundled source is `skills/skill-creator/SKILL.md`; copy its directory into a persistent, writable root of your choice, then point `AI_HELPER_SKILL_PATH` there or include that root in `AI_HELPER_SKILL_PATHS`.
- Do not use a checkout or extracted release directory as the long-lived writable root: upgrades should not remove user-created Skills or dirty the repository.
- The Skill never assumes a fixed runtime directory. It uses the shell server's resolved plural, singular, or default root configuration captured when the Skill is loaded.
- With one root it can create there; with multiple roots and no unique existing Skill, it asks which configured root to use instead of choosing arbitrarily.
- Explicit empty configuration fails closed, and paths outside the resolved roots are rejected by this workflow.

## Authoritative root metadata

- Exact-SHA Skill loads now replace `${AI_HELPER_SKILL_ROOTS_JSON}` and `${AI_HELPER_SKILL_ROOT_SOURCE}` with server-owned, non-secret values.
- Environment variables with those names cannot spoof the injected roots or source.
- The raw `SKILL.md` SHA and catalog version still depend only on the raw file; runtime substitution remains one-pass and never executes shell-like text.
- Expanded bodies are constructed against the 450 KiB budget instead of allocating an oversized intermediate string. Root count, visited entries, traversal issues, and public diagnostics are also bounded.
- Skill protocol is now **2**, while server protocol remains **11** and helper protocol remains **4**. Restart the foreground shell server, reload the unpacked extension, and refresh affected chat tabs after updating.

## Validation

The Skill validates new or updated files with a fresh challenge-free Skill list request. Dedicated tests cover plural/singular/default root resolution, plural-empty precedence, runtime placeholder injection, spoof rejection, bounded expansion/scanning/diagnostics, exact-SHA loading, source-release packaging, and catalog validation. Independent forward tests also verified successful creation in a unique temporary root and zero writes when two roots were ambiguous.
