# AI Chat Shell Exec v0.11.10

This release restores the complete Skill synchronization flow on the current Microsoft 365 Copilot chat DOM without weakening history, user-message, or protocol validation.

## Fixed

- Recognizes the current M365 assistant article class, `.fai-CopilotMessage[role="article"]`, in message discovery, generation-root binding, role classification, and helper scanning. The older `.fai-AssistantMessage` class remains supported.
- Handles M365 Copilot's current text layout, where a Skill helper's rendered `innerText` is one space-separated line while the same scoped content node's `textContent` retains the canonical protocol newlines.
- Confirms an auto-sent Skill sync prompt after M365 serializes it into a newline-free user-message text node, allowing the subsequent list helper to proceed instead of remaining blocked behind `submitted-unconfirmed` delivery state.

## Safety boundaries

- Canonical fallback is limited to the exact M365 assistant article and accepts only one whole, fully valid Skill envelope whose every canonical newline maps to exactly one ordinary space.
- Prefixes, suffixes, hidden fields, a second envelope, changed whitespace, a missing role, similar classes, and historical helpers remain rejected.
- Flattened prompt confirmation is limited to the exact fixed 12-line plugin-owned sync contract and requires a fresh exact M365 user-message root beyond the delivery baseline. Arbitrary multiline content, historical copies, suffixes, and different challenges cannot finalize it.

## Tests

- Added focused parser, role, generation, history, hidden-content, whitespace, fresh-root, one-finalization, suffix, and challenge regressions.
- Added a dedicated Chrome page running under the real `m365.cloud.microsoft` hostname. It verifies the collapsed `innerText`/canonical `textContent` pair, exactly one scanned Skill candidate, flattened prompt submission, Copilot list processing, catalog response, and silent ACK completion.
