# AI Chat Shell Exec v0.11.10

This release restores the complete Skill synchronization flow on the current Microsoft 365 Copilot chat DOM without weakening history, user-message, or protocol validation.

## Fixed

- Recognizes the current M365 assistant article class, `.fai-CopilotMessage[role="article"]`, in message discovery, generation-root binding, role classification, and helper scanning. The older `.fai-AssistantMessage` class remains supported.
- Handles M365 Copilot's current text layout, where a Skill helper's rendered `innerText` is one space-separated line while the same scoped content node's `textContent` retains the canonical protocol newlines.
- Accepts the single terminal layout newline currently left by M365's markdown reply node, while rejecting a second newline or any non-layout suffix.
- Confirms an auto-sent Skill sync prompt after M365 serializes it into a newline-free user-message text node, allowing the subsequent list helper to proceed instead of remaining blocked behind `submitted-unconfirmed` delivery state.
- Recovers a late-final list or acknowledgement only for the current tab's exact active challenge and synchronization phase; stale challenges, other tabs, later user turns, loads, and shell helpers remain inert.
- Treats an accepted late-final list/ACK semantic as an inert page-scoped tombstone across M365 replacement DOM roots, preventing redraws from repeating backend work or sending a protocol error to the AI.
- Writes known plugin-owned structured payloads to M365 in the exact newline-free form the host submits, preserving catalog JSON braces that Lexical otherwise deletes when they appear as standalone paragraphs. Ordinary text and existing user drafts are never flattened.

## Safety boundaries

- Canonical fallback is limited to the exact M365 assistant article and accepts only one whole, fully valid Skill envelope whose every canonical newline maps to exactly one ordinary space, plus at most one terminal layout newline.
- Prefixes, suffixes, hidden fields, a second envelope, changed whitespace, a missing role, similar classes, and historical helpers remain rejected.
- Flattened prompt confirmation is limited to the exact fixed 12-line plugin-owned sync contract and requires a fresh exact M365 user-message root beyond the delivery baseline. Arbitrary multiline content, historical copies, suffixes, and different challenges cannot finalize it.

## Tests

- Added focused parser, owner/phase, role, generation, history, hidden-content, whitespace, terminal-newline, backend-race, fresh-root, one-finalization, suffix, and challenge regressions.
- Added dedicated positive and negative Chrome pages running under the real `m365.cloud.microsoft` hostname. They verify the collapsed `innerText`/canonical `textContent` pair, exactly one scanned Skill candidate, flattened prompt submission, late-final owner recovery, brace-preserving catalog delivery, silent ACK completion, and rejection of a tampered prompt or later user turn.
