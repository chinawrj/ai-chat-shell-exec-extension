# AI Chat Shell Exec v0.10.0

This major feature release adds a local, user-facing Draw.io preview without changing the security boundary for executable helpers.

## Draw.io helper

The helper wraps the complete native `.drawio` file body:

````
ai-helper-drawio-start:architecture-v1
<mxfile>
  <diagram name="Architecture">
    <mxGraphModel>...</mxGraphModel>
  </diagram>
</mxfile>
ai-helper-drawio-end
````

The XML is data, not a shell command. It is never forwarded to the local WebSocket server, tmux, a board, `shell-output`, or the chat composer. The extension validates a bounded `<mxfile>` payload and renders it locally for the user with a pinned packaged Draw.io viewer.

Only the last complete valid helper is eligible. While a newer helper streams or renders, the previous SVG stays visible. The preview swaps atomically only after the fresh isolated renderer reports an SVG, so updates do not blank or flicker. An incomplete, malformed, stale, or renderer-failing helper keeps the previous diagram and records a bounded error log both in the preview and browser console.

The floating window is movable and resizable and includes the packaged viewer's zoom/layer toolbar, Close/Reopen, and Download `.drawio`. Closing and reopening are local UI actions and never rescan the chat or contact a backend. Diagram state is in-memory per page lifecycle and is cleared on route/reload rather than persisting potentially sensitive XML.

## Security and packaging

- Draw.io rendering runs in `drawio/viewer.html`, an unprivileged sandbox page without same-origin extension access.
- The official draw.io `viewer-static.min.js` from tag `v31.1.5` is bundled locally; runtime rendering does not use a CDN.
- The vendored SHA-256, Apache-2.0 license, attribution, upstream asset terms, and trademark independence statement are recorded under `extension/vendor/drawio/` and `THIRD_PARTY_NOTICES.md`.
- The Chrome extension release archive contains both `drawio/` and `vendor/`, including the viewer and its notices.
- Untrusted XML is passed as message data and is never injected into the host page with `innerHTML`.
- The payload limit is 1 MiB UTF-8 and the root must be `<mxfile>` with at least one `<diagram>`.

## Compatibility

This release bumps helper protocol compatibility from `2` to `3`; server protocol remains `9`. Reload the unpacked extension, refresh affected chat pages, and restart the foreground server:

```sh
./scripts/start_shell_server.sh
```

Use `./scripts/doctor.sh` to verify the extension/server protocol pair.
