# AI Chat Shell Exec v0.11.4

This maintenance release fixes helper results that were written into the AI chat composer but could remain unsent, lose their pending ownership after a route change, or remain permanently unconfirmed after a fast page refresh.

## Reliable send-only recovery

- While the current visible composer still contains the exact plugin-written result, the extension continues bounded send-only attempts in the same page lifecycle.
- The backend helper operation still runs at most once for that rendered request, and the extension still writes the result into the composer at most once.
- The five send-actuator functions remain byte-for-byte identical to v0.8.6/v0.8.9; this release changes only the durable outer ownership and recovery state machine.
- A slow or failed storage write no longer creates an awaited gap between the one composer write and the first send-actuator call.

## Submission proof and route safety

- A cleared composer enters `submitted-unconfirmed`: the extension waits for a fresh exact submitted-user-message root and never clicks or writes again while the composer is empty.
- Fresh proof is captured directly from the page mutation that renders the submitted message, before a normal retry delay, refresh, or SPA transition can erase it.
- `submitted-unconfirmed` ownership survives same-tab route changes. Exact plugin text can resume send-only delivery without a backend replay or composer rewrite.
- Deleting or replacing plugin text, or presenting a non-exact non-empty user draft, cancels the pending batch. Historical identical roots, remounted roots, non-matching messages, and an empty composer without proof cannot create a presentation receipt.
- M365 post-write ownership accepts localized composer labels containing `Copilot` while retaining exact text and host-signature checks.

## Clearer panel state

- The floating panel no longer observes its own status mutations as chat changes, eliminating the scan loop that could replace `Shell helper completed` with an already-handled message.
- Backend completion, exact text waiting to send, submitted-but-unconfirmed observation, and presentation-receipt retry are reported as distinct states.
- Force run remains hidden while a helper result still owns pending composer delivery.

## Validation

- The watchdog-protected route/delivery suite executes 16 explicit positive and negative cases, including same-lifecycle retry, delayed proof, immediate observer proof, historical-root rejection, receipt recovery, exact route handoff, and user-draft cancellation.
- An independent test seat verified the route cancellation case red-to-green and confirmed one backend operation, one composer write, and no receipt for negative cases.
- `./scripts/test_all.sh` passes, including private-tmux integration and the real unpacked-extension Chrome E2E covering hidden-tab MV3 timing, refresh, composer redraw, SPA route changes, Force run, and file delivery.

No server, shell-helper, Skill, or visual protocol version changed. Reload the unpacked extension and refresh affected chat tabs after updating.
