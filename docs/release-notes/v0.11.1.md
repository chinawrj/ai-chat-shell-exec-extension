# AI Chat Shell Exec v0.11.1

This maintenance release fixes the synchronization state for a healthy local Skills catalog that contains zero Skills.

## Empty catalog synchronization

- A zero-Skill catalog that has never been acknowledged now displays the green update action instead of being mislabeled as current.
- Synchronizing the complete empty list lets the AI remove stale entries from the fixed `AI_CHAT_SHELL_SKILLS_CATALOG` memory entry.
- After the empty catalog's real aggregate SHA is acknowledged, the panel returns to the neutral current state and does not repeatedly request updates.
- An AI-reported failure remains pending and can be retried normally. Force sync, origin isolation, challenge ownership, and fresh-SHA validation are unchanged.
- Removing the last local Skill changes the aggregate SHA and requests another synchronization; adding the first Skill after an empty acknowledgement does the same.

## Verification

Dedicated positive and negative tests cover first-time empty synchronization, silent acknowledgement, failed-update recovery, cross-origin isolation, current-state Force sync, removal of the final Skill, and dynamic panel text. The real-Chrome E2E now starts with an empty Skill root, completes the full memory handshake, and then verifies that adding the first Skill highlights the catalog again.

No shell execution, duplicate detection, composer actuator, tmux, or server protocol behavior changed in this release.
