# AI Chat Shell Exec v0.11.16

This release fixes first-response helper recovery against M365's current permanent-conversation URL shape.

## M365 first-conversation fix

- Current M365 assigns a new chat from `/chat` to `/chat/conversation/<UUID>`. v0.11.15 modeled only a direct opaque-id tail, so the additional `conversation` namespace was treated as ordinary navigation.
- That ordinary-navigation reset could discard active or pending response ownership. If execution had not started, the helper could be classified as initial history; if execution had started, its result could be rejected as stale. A later scan could show `Already handled` in either case without an AI-visible response.
- The route recognizer now accepts exactly one appended opaque id or one bounded short namespace followed by that id. This covers ChatGPT's `/` to `/c/<id>` or `/uc/<id>` routes and M365's real `/chat` to `/chat/conversation/<UUID>` route.

## Safety boundaries

- URL shape remains only the trigger for reconciliation. The exact latest user-to-assistant turn, unchanged user-text fingerprint, helper semantic/source position, original M365 DOM roots, one-time handoff, and four-second stable-route quarantine are still required.
- Origin, query, and hash must remain identical. Extra namespace levels, an oversized namespace, copied or replaced M365 roots, detached/reordered turns, changed helper content, and permanent conversation A-to-B navigation remain rejected.
- M365 DOM replacement is not newly trusted. ChatGPT remains the only host allowed to rebind a uniquely matching replacement turn through stable message identities.
- The pinned v0.8.6/v0.8.9 send actuator is unchanged.

## Regression coverage

- Focused tests cover the real namespaced M365 route, the legacy direct-tail route, unchanged query/hash state, query and hash mutations, excess namespace depth/length, exact-turn retention, copied-root rejection, and permanent conversation A-to-B rejection.
- Host-mapped real-Chromium tests now run completed-helper, outer-settings, backend-in-flight, inserted send-only, delayed replacement, post-write replacement, Skill-load, and permanent-route cases on `/chat/conversation/<UUID>`.
- Positive cases assert one backend request, one marker execution, one submitted result, no terminal `Already handled` state, and cleared pending/operation locks. Negative cases assert no stale composer or submitted-message side effect.
