# AI Chat Shell Exec v0.11.17

This release raises the default output allowance to 80,000 characters and fixes silent output loss when verbose shell commands push their START marker out of tmux history.

## Output defaults

- **Max output chars** now defaults to **80,000**, up from 20,000, in the popup, background shell/board requests, and local server.
- Saved settings and per-request overrides are preserved. Existing profiles with a saved value of 20,000 keep that value; set the popup field to 80000 and save to adopt the new default.
- The configurable range remains 1,000–200,000 characters.

## Verbose shell output recovery

- A valid DONE marker remains recognizable after START has left the pane history. A live run retains only the last bounded output previously captured under that run's START marker; unrelated pane history is never substituted.
- Missing output boundaries, output-size limits, and incomplete capture now produce `truncated: true`, including completion recovered from the status file or after a server restart.
- The AI-visible reply explains that an empty stdout does not prove the command produced no output. It explicitly asks the AI to continue reading the remaining output from existing logs/files in smaller ranges until complete. If missing output was not saved, the notice explains it cannot be recovered and recommends narrowing the query for needed information, without blindly rerunning commands with side effects.
- Observable pane changes still reset the output-idle clock after START loss. Failed recovery captures do not masquerade as new output activity.

This is a minimal fix using the existing bounded tmux capture path. It cannot reconstruct text evicted before the first capture or detect new output when the captured text stays identical, including changes beyond the capture prefix limit. Completion proofs, server deduplication, status-only recovery, and the pinned composer send actuator retain their existing behavior.

## Validation

- Focused real-tmux tests cover 30,000-line history rollover, the internal 1,000,000-character capture limit, retained verified output, idle behavior, and actual server-process loss followed by repeated status-only recovery without rerunning the command.
- Default-setting tests cover fresh/missing values and preservation of saved/request-specific values. Formatting tests cover partial and empty truncated stdout.
- Full automated suite: `./scripts/test_all.sh`, including real Chromium extension E2E.

## Installation

- Download the Chrome extension ZIP for the unpacked extension, or the source ZIP for the extension and local server.
- Update both components, restart the foreground shell server, reload the unpacked extension, and refresh affected chat tabs.
- `SHA256SUMS.txt` contains checksums for both ZIP files.
