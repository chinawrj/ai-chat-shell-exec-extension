# AI Chat Shell Exec v0.9.9

This release removes the obsolete 8000-character ceiling from ordinary AI shell helpers while retaining explicit resource limits around the script, transport, interactive command, logging, and delivery paths.

## What changed

- Shell helpers may contain up to 1 MiB of UTF-8 script text. Their complete bodies continue to run from private temporary `.zsh` files, so multiline scripts and heredocs no longer inherit a command-line-oriented 8000-character limit.
- Board and vision commands keep a separate 8000-character limit because those paths still submit one interactive line rather than a temporary script body.
- The WebSocket decoder rejects announced messages above 2 MiB before waiting for or buffering the full payload.
- Commands above the former limit are represented in responses and logs by a bounded preview, UTF-8 byte/character counts, and `cmdHash` instead of being echoed in full.
- Pending composer delivery accounting now includes the retained command body as well as the formatted reply, keeping large helper recovery within its existing total-storage budget.
- Server protocol 7 exposes `maxShellScriptBytes`, `maxInteractiveCommandChars`, and `maxWebSocketMessageBytes` in `/health`. Older foreground servers are rejected so the extension cannot silently reconnect to the obsolete limit.

## Validation

- Full `./scripts/test_all.sh` suite.
- Real Chromium unpacked-extension E2E executing and submitting the result of a 9000-character shell helper.
- UTF-8 byte-boundary, large-command echo, board/vision limit, health metadata, protocol compatibility, and pre-payload WebSocket rejection tests.

## Upgrade notes

- Restart the foreground shell server after updating.
- Reload the unpacked extension and refresh enabled chat tabs.
