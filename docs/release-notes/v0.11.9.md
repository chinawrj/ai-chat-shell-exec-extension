# AI Chat Shell Exec v0.11.9

This release completes a team-led P0/P1 review of the Skill routine and closes automatic-dispatch and composer-delivery races across history hydration, SPA routing, same-URL transcript replacement, and reused page DOM.

## Fixed

- A monotonic boundary is recorded and immediately persisted when composer ownership is first lost, including trusted Enter/LineBreak emptying. It prevents an older cancellation from erasing a helper created later—even across reload and when the empty composer is initially classified as submitted-unconfirmed until newer text appears. A final synchronous origin/attempt check also closes same-URL replacement after the async guard resolves.
- Automatic helpers now require proof tied to the latest explicit user turn and one exact current assistant response. Late-hydrated history, unknown-role content, an old response completing after a later user turn, and controls rendered inside authored content or the extension panel remain inert.
- Stable host Stop ids work with localized labels, while generic Stop text, removed-only controls without a prior epoch, and controls snapshotted from an old route cannot create generation evidence.
- Hosts may reuse a Stop DOM node for a genuinely separate response in the same route. The same node inherited from another route stays stale for the entire new lifecycle.
- A live response may cross one provisional-to-permanent URL assignment only while the exact response root remains current, user text is unchanged, and response text only appends. A second route or same-Element transcript rewrite fails closed.
- Skill backend results and pending replies retain exact root, render-generation, semantic-helper, transcript, page, and attempt ownership.
- Every first write, send-only retry, submission-proof check, cancellation, and finalization revalidates both the delivery attempt and exact Skill origin after asynchronous waits. A stale result cannot focus or write into another composer, send in another chat, accept copied proof, or clear a newer queue.
- Queued Skill replies may survive one settled exact-root URL assignment. Inserted and submitted-unconfirmed replies lose authority on a route change; same-URL transcript replacement and second-route cases discard only the stale exact entry.

## Recovery behavior

- Fail-closed historical executable helpers remain available through **Force run**.
- Fail-closed historical Skill helpers remain available through **Process Skill**.
- Valid retained-route delivery keeps the existing one-backend-operation, one-composer-write behavior.

## Tests

- Added focused positive and negative tests for localized stable Stop ids, authored/panel lookalikes, generic and removed-only controls, same-route Stop reuse, old-route stale reuse, later-user invalidation, one-route slow completion, second-route rejection, and same-Element transcript rewrites.
- Added deterministic await-race tests for queued, inserted, submitted-unconfirmed, and trusted-mutation delivery across route and same-URL transcript replacement. These exercise the production `attempt -> deliver -> insertReply` path and assert zero stale focus, write, send, receipt, or new-queue deletion.
- Expanded isolated real-Chrome Skill cases for atomic current responses, streamed route assignment, cold and late history, old-Stop/new-root rejection, exact queued route recovery, and unrelated-chat discard.
