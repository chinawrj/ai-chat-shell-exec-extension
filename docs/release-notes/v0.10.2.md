# AI Chat Shell Exec v0.10.2

This release removes broad command-text suppression that could reject legitimate helpers and makes the feedback-loop boundary depend on where a helper was rendered, not on words inside the command.

## Opaque command bodies

- Shell, board, and vision command bodies are no longer classified as copied output merely because they contain `shell-output`, `shell call result`, `shell call failed`, Markdown fences, terminal prompts, metadata labels such as `stdout:` or `cwd:`, or helper-marker text.
- Multiline scripts, strings, comments, documentation generators, and heredocs may therefore contain those values without being silently suppressed by the extension or refused by the shell server.
- Empty commands, shell script size limits, board/vision single-line and length limits, helper envelope parsing, tmux ownership, serialization, and authoritative server duplicate adjudication remain unchanged.

## Structural feedback-loop protection and Force run

- Automatic scanning still suppresses a helper when its exact rendered provenance is a fenced or DOM-labelled `shell-output` block. This prevents extension-generated results from recursively executing copied helper examples.
- Ordinary mentions of `shell-output` are no longer sufficient to classify an entire message as tool output; chain state recognizes only complete known result envelopes, including the exact M365 flattened representation.
- **Force run** explicitly bypasses the structural suppression and authoritative duplicate decision. Neither the extension nor server performs a second command-keyword veto.
- Obsolete frontend functions that reconstructed commands from historical shell-output have been removed.

## Validation

- Unit coverage proves extension, shell server, board, and vision validation treats formerly suspicious command text as opaque data while retaining structural and size constraints.
- Real Chromium E2E executes a keyword-heavy heredoc through the extension and temporary shell server.
- The same E2E renders another keyword-heavy helper inside `language-shell-output`, proves it has no automatic side effect, clicks **Force run**, and then requires its real tmux side effect and shell result.
- The full static, unit, tmux integration, packaging, and Chromium extension suite is required before release.

## Upgrade note

Restart the foreground shell server after updating. This release requires server protocol 10 so an older server cannot silently retain the removed command-text rejection behavior.
