# AI Chat Shell Exec v0.11.5

This release adds an explicit installation lifecycle for local Skills and makes installation state part of the versioned catalog synchronization contract.

## Local Skill installation

- Every newly discovered Skill starts uninstalled.
- The expanded Skills list shows every discovered Skill with `Install`, `Installing…`, `Installed`, retry, or missing-installer state.
- Installation accepts only a trusted click followed by a native confirmation naming the Skill; synthetic page clicks and cancelled confirmation do nothing.
- Installation binds the exact Skill and installer SHA, executes a private immutable snapshot of the real non-symlinked adjacent `install.sh` with a minimal environment, and only exit code 0 plus fresh unchanged Skill/installer validation marks it installed.
- Installer failures and bounded diagnostics remain local. Installation never writes a result into the AI composer and never uses tmux, Force run, shell command ledgers, or duplicate adjudication.
- Concurrent clicks and requests are serialized, stale id/SHA/catalog requests fail closed, changed Skills remain uninstalled, and timed-out installer process groups are terminated.

## Versioned installation state

- Installation state is stored in the fixed `skill-install-state.json` file under the `AI_CHAT_SHELL_STATE_DIR` directory, alongside the existing catalog state.
- The schema-v2 state file is atomically replaced with mode `0600`; installed records require a server-authenticated receipt backed by a separate private key, so manually setting `installed:true` fails closed.
- Adding or deleting a Skill, changing a `SKILL.md` or installer, changing an effective installed state, or repairing a malformed/mismatched/forged record advances the monotonic local Skills version and makes the panel chip pending/green.
- Formatting, JSON field order, and `updatedAt`-only rewrites do not create false updates.
- A changed `SKILL.md` or `install.sh` automatically resets that Skill to uninstalled until the current exact installer succeeds again.

## AI catalog contract

- Only installed and loadable Skills are included in the catalog sent to AI or eligible for Skill load.
- The update reply includes each installed Skill's id, name, full bounded description, and SHA.
- The runtime contract explicitly requires replacing the single `AI_CHAT_SHELL_SKILLS_CATALOG` memory entry and preserving every name and description as routing metadata. Skill names and descriptions are treated as untrusted metadata, not executable instructions.
- The AI must echo both aggregate catalog SHA and monotonic `catalog-version`; acknowledgement validates both against the challenged list and a fresh scan, so an installation-state-only change cannot be mistaken for an already synchronized catalog.

## Validation

- Focused server tests cover default-uninstalled state, success, idempotence, nonzero exit, missing/symlinked/oversized installers, stale Skill/installer requests, immutable snapshot/TOCTOU behavior, timeout, mutation during install, minimal environment, concurrency, authenticated state repair, JSON spoof rejection, and meaningful-versus-metadata-only changes.
- Background and content tests cover version-only pending state, exact version acknowledgement, installed-only catalog replies, complete descriptions, trusted/cancelled clicks, panel lifecycle closure, local retry/recovery, and double-click single flight.
- Real unpacked-extension Chrome E2E clicks Install, proves one installer execution, verifies the JSON false-to-true transition, confirms no composer output from success, checks Skill-change reset/reinstall, and completes the latest catalog acknowledgement flow.
- `./scripts/test_all.sh` passes.

The Skill protocol is now version 3. Restart the foreground shell server, reload the unpacked extension, and refresh affected chat tabs after updating.
