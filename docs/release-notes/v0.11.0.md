# AI Chat Shell Exec v0.11.0

This release adds a safe local Skills catalog that lets an AI discover Claude-compatible `SKILL.md` metadata, keep one stable memory catalog current, and load the full content of a relevant Skill only when needed.

## Local Skills catalog

- The server recursively discovers configured `SKILL.md` files, validates their frontmatter and file boundaries, computes each raw file's SHA-256, and derives one aggregate catalog SHA without an additional effective hash.
- The aggregate SHA drives a persisted monotonic local version. Moving an unchanged file does not alter the catalog identity; changing its raw content does.
- List, rescan, and load are bounded high-level server operations. They never run shell commands, use tmux, enter command duplicate history, or become eligible for **Force run**.
- Loads require an exact catalog id and full file SHA, revalidate the file, and perform one-pass substitution only for built-in or explicitly allowlisted environment variables. Unknown placeholders remain literal and missing allowlisted values fail closed.
- Automatic status checks share a 10-second server snapshot across tabs, while list, load, rescan, synchronization start, and final acknowledgement checks are fresh. Discovery is capped at 500 files, depth 12, 384 KiB per file, and 32 MiB total.
- The actual serialized catalog is capped at 350,000 characters. An oversized catalog becomes unhealthy instead of being reported as successful and later truncated in the composer.
- The server sizes the exact final dynamically fenced Skill-load reply and rejects anything above 500,000 characters before returning the expanded body. The extension verifies the same count as a second fail-closed boundary.

## Memory synchronization

- Each AI site origin synchronizes one fixed memory entry named `AI_CHAT_SHELL_SKILLS_CATALOG`, containing only catalog version/SHA and Skill id, name, description, and SHA metadata—not full Skill bodies.
- One tab per origin owns the short-lived update challenge. Cumulative local edits collapse to the latest catalog, and stale, cross-tab, cross-origin, wrong-memory-entry, or wrong-SHA acknowledgements are rejected.
- The same owner tab may explicitly force a replacement challenge after refresh or response loss; another tab cannot take it over, and a tab that closes during startup cannot leave a 10-minute orphan lock.
- Every runtime synchronization prompt explains which memory entry to replace and the exact acknowledgement/failure response contract. It deliberately describes the Skill helper delimiters indirectly so the extension cannot scan its own prompt as a helper.
- The stable Custom Instructions only explain when and how to load relevant Skills; volatile synchronization mechanics remain in runtime prompts.

## Panel and diagnostics

- The compact panel displays `Skills vN`. It is highlighted green while an update awaits acknowledgement, remains visibly pending after an AI-reported failure, and shows an error state for an invalid local catalog.
- The expanded Skills group can inspect the catalog, rescan local files, or force a fresh synchronization even when the current SHA was previously acknowledged.
- Shell functionality remains available when the Skills catalog is invalid; the panel and server health expose the catalog diagnostics separately.
- Explicitly recognized user messages—including M365 user-message descendants—cannot acknowledge Skill memory. M365's flattened plugin-written Skill output is recognized only through recent exact delivery ownership, while similar human text remains a real prompt.
- M365's exact plugin-output provenance expires at 60 seconds and is scoped to the same page identity; expired, cross-page, prefixed, or suffixed lookalikes remain ordinary user prompts.
- AI-facing catalog and load failures contain stable error codes and safe relative identifiers, not absolute local paths. Detailed filesystem failures stay in the local server console.

## Compatibility and verification

Server protocol is now **11**, helper protocol is **4**, and Skill protocol is **1**. Restart the foreground shell server, reload the unpacked extension, and refresh affected chat tabs after updating.

Dedicated positive and negative coverage now exercises catalog hashing and safety bounds, environment expansion, protocol isolation, multi-tab ownership, stale acknowledgements, self-generated prompt suppression, durable composer delivery, panel states, and the complete real-Chrome synchronization/load flow.
